# 知途 Web

知途当前正式 Web 入口，基于 Next.js、React 和 React Flow。该实现由 `prototypes/demo3` 验证后提升而来，保留组长版本的产品结构与交互。

## 本地启动

需要 Node.js 22 或更新版本。

```powershell
cd apps/web
npm install
npm run dev
```

打开 <http://127.0.0.1:5173/workbench>。

端口必须是 **5173**.后端的 CORS 只放行 5173 / 3000：换到别的端口会在浏览器里被 CORS
拦掉，注册/登录全失败，而报错只在浏览器控制台，后端日志里什么都看不到。

## 主题

**当前是暖白主题，不是深色。** 颜色集中在 `src/app/dark-theme.css`。这个文件名是历史
遗留 —— 它的**最后一层**
(`/* Final light-theme layer. Keep this at EOF so legacy dark rules cannot win. */`)
把整套变量覆盖成暖白(`--bg:#f8f6ef`、`--surface:#ffffff`、`--text:#24384d`),上面残留的
深色规则全部被它压住。改颜色请改那一层；在它之前插规则不会生效。

## 当前交互

1. 未登录访问正式页面时进入登录页。
2. 注册/登录之后落到**成长空间列表**（`/spaces`）—— 一个刚注册的账户一个空间都没有，
   页面不会给他一份别人的计划。在列表里新建一个空间，填名称和「想在这里推进什么」。
3. 建完直接进工作台，画布上**只有这个空间的根目标**，没有别的节点。
4. 「新建节点」建子节点；双击节点进入它的子空间，成为下一层中心；面包屑或返回按钮回到上级。
5. **节点之间可以自己连线**（2026-09-27 起，见下面一节）：在节点右侧的圆点上拖出一条线，
   或者用工具栏的「建立关系」表单选起点终点。拖完/选完弹出关系编辑器：选类型、写说明。
   **点线**可以再打开它改或删（删线不删节点）。
6. 工作台有四个视图（路径 / 时间线 / 任务 / 排期），它们画的是**同一份** `/plan`。
7. 「我的」页面可以编辑个人资料、目标方向和目标年份，也可以退出并切换账户。

### 三种关系长什么样，以及为什么默认是「相关」

| 类型 | 画法 | 意思 |
| --- | --- | --- |
| `depends_on` | 实线 + 箭头 | **前置 → 后续**：前者做完才轮得到后者。会真的改变排期 |
| `related_to` | 虚线，无箭头 | 对等关联。谁先谁后都一样，**不影响排期** |
| `influences` | 虚线 + 箭头 | 前者影响后者，但不构成先后 |

**拖线默认落「相关」，而且拖完先不写库** —— 弹出来的是「建立关系」表单，起点终点就是
你拖的方向，确认那一下才写。两个理由：

- 把两个东西拖到一起**不等于**它们有先后。猜成「前置」会真的改变排期结果，所以由用户说。
- 「相关」是**无向**的，后端按 UUID 排序规范化两端。所以"先落一条相关、再在编辑器里改成
  有向的影响"这条路会把方向交给 UUID 的排序 —— 用户拖的方向一半的运行里会被翻过来。
  一次确认、一次写入，方向就永远是用户拖的那一个。

后端不支持的转换在界面上是**灰的**：`related_to ↔ influences` 可以换，换成/换出
`depends_on` 不行（跨表，写在上面的说明会丢），编辑态那个选项被禁用并写明原因。

**下面这一条连同示例空间一起删掉了，别再照着写**：根路径展示"学业成绩、科研能力、
综合经历、个人成长"四个分类，以及"添加树叶"这个叫法。那四个分类是示例空间那份演示数据
里写死的（后端没有 `category` 这个字段），"树叶"是那棵树上的说法。现在用户自己建的
节点就叫**节点**。

## 数据边界（2026-09-26 校准）

这一块此前写的是"当前账户系统只用于前端产品验证，不是正式身份认证"、"对话是 Mock
响应，尚未接入真实 AI"。**那两句话已经不成立**,留着它们会让读到的人照着过时的约束
做决定。现在的真实情况是:

- **后端已接入。** `src/lib/api.ts` 是统一的 API 客户端(`apiFetch` + bearer token),
  登录/注册走 `POST /api/auth/*`。token 存在 `localStorage`。
- **演示空间已经整个删掉了。** `?workspace=primary` 那份存在浏览器里的保研演示数据
  （整棵树、四分类、四条预置对话、两篇随笔、写死的假回复和假「今天」观察）连同
  `src/mock/` 一起没有了。现在**只有一种空间**：后端的、属于这个账户的。
  `features/growth/provider.tsx` 里的 `SpaceInfo['kind']` 是 `'real' | 'none'`，
  `none` 是"还没打开任何空间"这个**正确的空状态**，不是"示例状态"。
- **`localStorage` 里还剩什么。** 只剩三样，都不是业务主存储：令牌
  （`src/lib/api.ts`）、当前选中的空间 id、**画布上的节点位置**（按账户 + 空间分键）。
  **计划、对话、随笔的正本都在后端**。`grep localStorage` 仍然是最快的答案。
  - **位置那一份从 2026-09-27 起不再是唯一的那一份**（提交 `53762a2`，步骤 3B）：它同时
    写进后端的 `node_positions`，打开空间时**以后端那份为准**（服务端认识哪个节点就用
    哪个节点的那一行，本地没被覆盖的照旧）。localStorage 这份留着是"这台机器上的偏好"，
    也是读不到后端时画布还有东西可画的那一份。
  - **视口也接上了**（同一提交）。它以前只活在 Provider 的内存里（`viewports`，按层级，
    2026-09-27 提交 `c65959e` 从组件里提上来的），跨一次刷新就没了。现在每层的平移缩放
    写进 `scope_viewports`，打开空间时 `GET /layout` 读回来，**按用户取、不按空间共享** ——
    所以换台机器打开是同一个画面。
    - 保存**攒 600 毫秒整份提交**（`PUT /layout` 的语义就是"最后一次赢"，见
      `lib/backend.ts` 里 `PutLayoutRequest` 的注释），而且**同一时刻只有一个请求在飞**：
      两个并发时先发的那个可能后落地，用户会看到自己拖过的位置在刷新之后回到别处。
    - **切空间不会把上一个空间那份写进新空间。** 待发的数据留在闭包里，定时器和它捕获的
      `space.id` 一起被丢掉 —— 所以卸载时**故意不取消**那个定时器：它属于上一个空间，
      数据也只该进上一个空间。另一道：令牌变了（登出、换个人）这一份就作废。
    - **存不上会说出来**，工具栏里一行红字加一个「重试」（载荷是点的那一刻现拼的，
      所以重试不是空转），**不自动重试** —— 那会把"后端一直存不上"变成"界面一切正常、
      刷新就丢"。
    - **自动 fit 等 `layoutReady` 再跑**：后端那份还没回来就 fit，等于拿默认视角盖掉用户
      上次摆好的位置，而且那次 fit 的视口会被当成"用户设的"存回去，把库里那份也改掉。
    - 时间线那一份（`timelineViewport`）**仍然只在内存里**，没有落库。
    - 已知两个窄口，这一版没处理：①600 毫秒内**整页刷新**（不是应用内跳转）那一份会跟着
      页面一起没 —— `sendBeacon` 带不了 `Authorization` 头；②在子空间里拖动**它自己的
      根节点**，位置和它在上一层作为子节点的那一份是两行，而 `node_positions` 一行只装得
      下一个，存的是"归属层级"那一份。
    - 在这之前它哪儿都没存，于是**切一下视图回来，画面就跳回原处** —— 见
      `docs/10-NEXT-BATCH-SCOPE.md` 第 4 节（那一节现在是已修的记录）。
  - **画布上还没提交的输入住在 `features/growth/drafts.ts`**（同一提交）。它是个**模块级
    Map**，键是 `${workspaceId}:${scopeId}`，只在内存里：工作台的四个视图是一个三元表达式，
    切一下页签整棵画布子树就卸载（ReactFlow 的视口、弹窗那一组 state 全跟着没），
    所以这些输入不能住在组件里。只活在内存是有意的 —— 跨一次整页刷新把一份"用户早就离开、
    可能不想要"的输入重新摆到他面前，他看到的东西会和记忆里对不上。
    **只有用户明确关掉弹窗（× / Esc）才丢**，卸载不丢。
    关系编辑器（起点、终点、类型、说明）也在这一份草稿里：拖线拖到一半、字写了一半
    被切走，回来还在。
  - **这一份的边界要读准：它只活"一次页面运行"**（2026-09-27 校准）。刷新就没了 ——
    所以它**不能**被说成"草稿可恢复"、"写了一半不会丢"。跨刷新的那一份留给后端
    （步骤 4 的正文草稿），不在这里用一个半成品顶替。
  - **它也不许活得比账户长**（2026-09-27 补，提交 `b30ca68`）。模块级状态不跟着组件走，
    所以退出登录 / 换个人登进来时由 `AuthProvider` 里一个"身份真的变了"的 effect 整份
    清掉（`drafts.clearDrafts()`）。原因具体：键里那个空间 id，真实空间是各自的 UUID
    串不到一起，**唯一所有账户共用的是"还没进空间"的那一份** —— `'none'`（`NO_SPACE`）
    配层级哨兵 `'goal'`。`canvas-stability.spec.ts` 有一条用例把画布**停在那个键上**
    （挂住 `GET /api/workspaces/{id}`，并先断言根还是哨兵 `'goal'`），然后甲登出、乙登进，
    断言甲的弹窗和文字一样都不许出现。那条用例**先证明过它会红**：把 `clearDrafts()`
    掏空重跑，它红在"甲那边开着的新建弹窗跟着过来了"。
  - 顺带：`window.__zhituCanvasLifecycle`（只给测试看的那根挂载记录）现在**封顶 50 条**
    （`PathView.tsx` 的 `CANVAS_LIFECYCLE_LIMIT`）。它写在全局对象上、正常使用里每切一次
    视图就涨一条、谁也不清。封顶会让"没涨过"这类断言变成恒真，所以那条用例会先确认
    "没数到上限"再断言 —— 数到上限时它以"这条断言失去意义"红掉，而不是安静地绿。
- **已知的内存态缺口（未修，但已经排进下一批）**：随笔（`publishJournal`）与空间文件
  （`addFiles`）目前**只写前端内存**——后端还没有随笔表、随笔接口和资源上传接口。刷新
  之后新写的随笔会消失，附件也只是浏览器会话里的对象地址。`tests/experience.spec.ts`
  里有一条写明原因的 `test.fixme` 钉住前者；`level-navigation.spec.ts` 只证明文件
  **在同一次会话内**按层归属，没有断言跨刷新还在。**范围决定写清了**：随笔这一批做掉
  （那条 `test.fixme` 应当变成真断言，不是删掉了事）；空间文件要单独定上传、存储、权限、
  生命周期，**在它落库之前界面上要写明"临时附件，刷新后失效"** —— 这一句已经先改了
  （`SpaceFiles.tsx` 原来是「仅本次会话保留」，不算说谎，但没把"刷新就没了"说明白）。
  见 `docs/10-NEXT-BATCH-SCOPE.md`。
- **模型输出只是提案。** 计划变更要在界面上点击确认才落库。界面上有一个徽标显示这次
  回复是谁生成的(openJiuwen / 直连模型 / 本地规则),它来自响应的 `source` 字段 ——
  不是装饰。
- 空间文件只在浏览器会话中创建本地对象地址，不上传服务器。
- “树叶”是 `GrowthNode` 的界面称呼。
