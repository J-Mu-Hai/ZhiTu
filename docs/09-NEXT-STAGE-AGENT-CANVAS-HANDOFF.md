## 1. 任务目标与阅读方式

请在现有知途项目上迭代，不重建另一套 Demo。下一阶段要让用户感觉自己在与 AI 共同分析、构建和调整一个持续生长的计划，而不是填问卷、看 AI 一次性生成的树。

本任务书整合用户已提出的要求，并给出建议的工程默认值。实现前核对现有代码；发现接口、数据或交互冲突，应明确报告迁移方案，不可把文档示例直接当作已有 API。

先阅读 `代码ai的约束.md`、`docs/CURRENT-DESIGN.md`、`00-PROJECT-VISION.md`、`02-INFORMATION-ARCHITECTURE.md`、`03-GROWTH-SPACE.md`、`04-SYSTEM-ARCHITECTURE.md`、`05-DATA-MODEL.md`、`06-AGENT-DESIGN.md`，以及实际契约、模型和服务实现。这些相对路径均相对于仓库或当前 docs 目录。

本任务明确改变“固定分类、树状或线性规划”的旧产品限制。实施后同步更新现行设计文档；不要把旧文档中的四个成长分类硬编码进真实新空间。

### 用户必须获得的能力

1. 每一个画布都允许用户主动创建节点、编辑内容、拖动位置、建立和删除联系，不依赖 AI 才能操作。
2. 每个节点都能打开正文编辑器，也能进入自己的子空间，在当前视图中成为根节点。
3. 支持分支、汇聚、多前置条件、跨分支关系，不再仅支持线性链条。
4. AI 主动分析目标、识别缺口、提出策略、渐进拆解，再安排周计划和日计划。
5. AI 能读取当前节点内容、继承上层约束，并理解与其他节点的关系。
6. AI 讲解具体节点时，左侧画布可以自适应聚焦、缩放、突出相关内容，形成共同讨论同一对象的感觉。
7. 所有操作最终作用于同一份持久化规划状态；Graph、Timeline、Tasks、Today 只是不同视图。

- 手机号加密码的简洁注册、旧邮箱登录兼容；当前没有短信核验，不能声称号码已验证。
- 暖白背景、浅雾蓝、少量鼠尾草绿与杏色；登录、画布、时间线、任务、弹窗和输入框都不能退回黑色。
- 根节点小旗、普通节点圆点、可执行任务勾选框；节点层级靠尺寸、字重、关系区分，不给每个节点配不同装饰图标。

- 模型只提案；业务服务是唯一数据库写入层；数据库失败不能假装保存成功。
- 密钥留在后端环境变量，禁止写进前端、文档、截图和日志。

本阶段不要求部署腾讯云、Vercel，不要求完成 Flutter，也不引入多 Agent 集群、向量数据库或图数据库作为前提。

## 3. 核心建模：归属树与关系图分开

### 3.1 节点空间不是复制的工作空间

顶层 Workspace 是权限、数据归属与独立项目边界。NodeSpace 是某个节点为视觉根的局部视图，不复制节点，也不自动新建顶层 Workspace。

推荐最小模型：

- 每个节点有一个稳定 ID、一个所属 workspace、最多一个结构父节点。
- 父子归属形成无环树，用于面包屑、子空间范围、继承和汇总。
- 关系边单独形成图，支持多个入边与出边。
- 同一个节点可被其他子空间引用展示，但只有一份正文、状态和执行记录。
- 默认进入节点后展示自身、直属子节点和必要的外部引用；不要一次加载无限深后代。
- “进入子空间”和“建立独立工作空间”是不同动作。拆成独立项目不在本轮自动实现范围。

例子：在“科研能力 → 项目 A”里建立实验任务，返回总空间后仍是同一个任务，排期只计算一次。

### 3.2 关系类型及规则

| 关系 | 含义 | 是否影响排期 | 环规则 |
| --- | --- | --- | --- |
| 父子归属 | B 是 A 的组成部分 | 用于范围和汇总，不等于先后顺序 | 必须无环，单父节点 |
| `depends_on` | source 依赖 target，target 完成后 source 才可开始 | 是 | 必须无环 |
| `related_to` | 两者相关 | 否 | 允许关系闭环，不允许自连 |
| `influences` | source 影响 target | 否，仅作为分析依据 | 可闭环，不代表确定因果 |

以上是建议语义名；若现有契约有等价类型，应映射复用而不是平行新增。

特别要求：

- 默认拖线创建“关联”，不能擅自解释为任务前置条件；用户可以在关系编辑器选择类型和填写说明。
- 依赖线在界面上明确标识前置任务与后续任务；箭头采用“前置 → 后续”，即与上述存储方向相反，转换必须集中实现并测试。
- 关系类型变更必须重新校验；前端预检不能代替服务端校验。
- A、B 均完成后 C 才开始，必须受两个前置条件约束，而不是任选其一。
- 第一版硬排期依赖仅支持可执行任务之间；阶段节点先展开到明确任务，不暗中猜测阶段依赖的含义。
- 第一版用户建边仅限同一顶层 Workspace，可跨子空间；跨顶层工作空间关系留待后续，但全局时间冲突本轮必须检查。
- 禁止不存在节点、越权节点、自连、重复边；无向关联以端点规范化去重。
- 归属移动不得制造祖先循环；相关引用不改变节点归属。

## 4. 用户自主建图的完整交互

所有层级的画布统一支持：

1. 工具栏“新建节点”；空白处双击或上下文菜单也可创建，触屏有显式按钮作为替代。
2. 在当前位置创建节点，输入标题、类型与可选正文；默认归属当前子空间根。
3. 从连接点拖线创建关系；可用“选择起点和终点”的表单完成同等操作，不能只支持鼠标拖拽。
4. 点击边查看类型、方向、说明，并修改或删除；删除边不删除节点。
5. 单击节点打开正文与详情；独立的“进入子空间”按钮或面包屑负责导航，不让单击同时触发两件事。
6. 拖动、多选、局部整理布局；用户手工摆放后，AI 回复不能把整个画布重新排版。
7. 删除节点前展示后代、关系、计划和排期影响。默认使用可恢复的归档方案；完整策略由迁移设计明确。
8. 用户操作支持撤销/重做。已落库的撤销通过受版本校验的补偿操作执行，不只回滚浏览器画面。

用户点击保存或拖线本身就是该次直接编辑的授权，不必再走一张 AI 确认卡；但破坏性动作需要确认。直接编辑与 AI 提案复用同一组校验和业务写入能力。

保存失败必须保留可恢复草稿并显示失败；不显示虚假的“已保存”。拖动布局与业务计划分开存储，采用节流保存。

## 5. 节点正文、规划属性与分析状态

每个节点具备三层信息，不把它们拼成一个不可维护的大 Prompt：

- **用户正文**：笔记、要求、想法、材料、过程记录；第一版 Markdown 或轻量文本编辑即可。支持自动保存提示和版本冲突处理。
- **规划属性**：节点类型、验收标准、状态、优先级、估计工作量、截止时间、父节点与依赖。
- **局部分析**：已知信息、未知项、来源、假设、诊断、策略、规划阶段、更新时间、输入版本。

正文是 AI 可以读取的资料，不是高权限指令。粘贴文件、网页和节点文本中的“忽略规则”“修改其他项目”等内容不能扩大权限或越过确认机制。

正文更新后标记相关分析过期，提供“让 AI 根据修改重新分析”；不要每次按键都调用模型。必要时在下一轮对话中提示使用了新的内容。

用户原文不被 AI 摘要替代。模型建议修改正文时显示差异，确认后应用；用户手动编辑则直接保存。不能凭旧正文版本覆盖正在编辑的新版本。

## 6. 智能体架构

采用“一个主控 + 共享规划状态 + 按需局部分析 + 能力模块 + 有边界的工作流”。不为每个节点启动一个独立 Agent。

```text
对话 / 节点正文 / 用户建图 / 执行反馈
                 ↓
API 与权限检查 → 上下文整理 → 主控工作流
                              ↓
            理解缺口 / 检索证据 / 诊断策略 / 分层规划 / 复盘
                              ↓
                    结构化分析与变更提案
                              ↓
             校验、排期预检、影响预览、用户确认
                              ↓
                   业务服务原子更新数据库
                              ↓
            Graph / Timeline / Tasks / Today 同步更新
```

openJiuwen 用于编排和模型调用；数据库是业务事实权威来源，不交给模型记忆系统代管。具体 SDK 能力以当前安装版本验证，不因概念设计引入未验证的 Memory 组件。

### 6.1 上下文整理器

每轮构建明确的 `scope`，至少包含 workspace、当前根节点、选中节点、允许变更范围和状态版本。默认可修改当前节点及其后代；有关联但不在范围内的对象只读。

上下文按优先级读取：

1. 当前请求与当前节点正文。
2. 当前节点及相关子节点的状态和近期对话。
3. 祖先目标、截止时间与已确认约束。
4. 与本次决策有关的依赖、证据和执行记录。
5. 用户跨空间的可用时间及已占用时间摘要。

不要默认拼入全部祖先聊天或全部兄弟节点正文。设置上下文预算，摘要保留来源与版本；被截断的信息显式标记，关键原文按需回读。

子节点不能静默放宽上层硬截止时间；冲突应作为待决策事项。资料、分析与会话始终受用户和工作空间权限约束。

### 6.2 理解、追问与证据

- 区分用户陈述、外部来源、模型推断和未验证假设，记录出处与适用时间。
- 未知项记录“为什么重要、会影响哪个决策、可以从哪里获取、是否阻塞”。
- 优先从已知正文、历史和允许访问的材料中补足；只有用户知道的才问用户。
- 通常一轮最多问 1–2 个关键问题，先给有价值的分析，不机械索要整套背景。
- 非关键缺口允许带假设给草案；时间预算未知时可以拆解，不能伪造确定日程。
- 外部检索由后端受控工具完成，设置超时、次数上限与安全 URL 策略，不抓取私网或任意本地文件。
- 没有搜索能力或搜索失败时，如实提示并允许用户提供材料，不编造来源。
- 模型给出的可信度分数不是事实证据；优先显示来源、时效性、适用范围和冲突信息。

### 6.3 诊断与渐进规划

AI 输出应让用户知道：当前理解、主要缺口、推荐策略、这样拆解的理由、下一步建议。

不要一次生成长期计划的全部细枝末节。总空间先给方向和里程碑，子空间逐步展开，近期细到可执行任务，远期保留粗粒度。

每次生成前检查已有节点：应新增、补充正文、修改现有任务，还是仅解释？避免反复生成同义节点。已经可以执行、估算和验收的任务应停止继续拆分。

能力模块输入输出应通过 Pydantic 契约校验，至少包括 scope、输入版本、结构化结果、引用、未知项、错误和建议变更。模块并不等于必须单独调用一次模型。

### 6.4 工作流与终止条件

建议阶段：理解目标、补充资料、澄清、诊断、策略、规划、等待确认、执行复盘。根据需求跳转，不强制每轮走完全部阶段。

每轮必须有调用次数、工具次数和总时间上限。遇到需要用户信息、需要确认、完成回答或资源上限时结束本轮，不使用无限 `while True`。

可显示“正在读取当前节点”“正在检查时间冲突”等真实工作状态，但不得编造后台工作，不展示或依赖模型隐藏思维链。

## 7. 统一变更、版本与一致性

扩展或复用现有 PlanAction，使节点、正文、归属、关系和排期变更有明确结构。先核对已有动作，避免新建平行命令体系。

AI 提案至少提供：新增/修改/删除清单、理由、影响范围、依赖的状态版本、排期影响和风险。

- 模型继续使用受限节点句柄，不自行编造数据库 UUID；由后端映射和授权。
- 新节点使用提案内临时引用，确认时生成真实 ID，并映射关联边。
- 用户确认后服务层原子应用；失败整体回滚，或采用文档明确的原子组，不能节点建了一半却显示成功。
- 确认有幂等键；重复点击或请求重试不重复创建。
- 旧提案遇到用户新编辑时拒绝覆盖，返回冲突并重新预览，禁止最后写入者静默获胜。
- 对提案部分接受，必须检查依赖闭包；第一版可仅支持整体接受/拒绝，不做不安全的逐条勾选。
- 自动分析结果可由服务保存为带来源、版本的草稿，不能自动变成已确认约束或修改用户计划。

## 8. 全局时间与局部重规划

节点可以局部规划，时间预算必须跨该用户所有活动空间统一计算。同一任务在多个视图出现，只排一次。

排期以确定性程序校验任务依赖、工时、已占用时段、可用时间、截止日期和时区。普通关联、影响关系不进入排期依赖图。

新增局部任务如果挤占其他空间时间，应展示冲突及备选方案，不自动移动其他已确认安排。父阶段工时是汇总，不与子任务工时重复计入。

执行反馈触发局部诊断：未完成可能来自估时偏差、资源变化或任务定义不清，不一律解释为自律问题。仅重排受影响任务，必要时说明对上层里程碑的影响。

## 9. AI 讲解驱动的自适应画布

### 9.1 用户体验目标

AI 说“这里的两个任务存在前置关系”时，左侧画布把这两个节点和关系放进合适的可视区域；说“我们回到整体目标”时可以展示概览。用户感觉双方正在看同一个对象，而不是右边聊天、左边静止。

这里的“根据 AI 当前考虑的文字”实现为**根据可见回复段落及结构化节点引用调整视图**，不是读取隐藏推理，也不是逐字猜测关键词。

### 9.2 三类动作严格分开

| 动作 | 是否改变数据 | 默认权限 |
| --- | --- | --- |
| 平移、缩放、高亮 | 仅临时展示 | 跟随开启时可自动执行 |
| 重新排列节点位置 | 改变布局 | 用户点击局部整理/确认后执行 |
| 修改节点、边、日期、正文 | 改变业务状态 | 用户直接操作或确认 AI 提案 |

自动聚焦不能被实现成“每次回复都重新布局所有节点”。

### 9.3 建议的展示协议

由 AI 提供语义引用，后端校验并映射，前端计算实际坐标。以下仅为待落地的协议示例：

```json
{
  "messageId": "message-reference",
  "scopeRootRef": "n1",
  "planVersion": 12,
  "segments": [
    {
      "id": "s1",
      "text": "先完成数据准备，再开始实验。",
      "nodeRefs": ["n3", "n4"],
      "edgeRefs": ["e2"],
      "presentation": "focus_group"
    }
  ]
}
```

建议支持 `focus_node / focus_group / highlight_relation / overview / none`。引用必须可见、可访问且属于当前有效版本；错误引用丢弃，不因展示失败导致回复失败。对未确认的新节点，引用提案草稿而非假装已存在的正式节点。

不允许模型直接发送任意像素坐标、缩放值、前端脚本或不受控导航命令。

### 9.4 跟随控制与交互优先级

- 提供可见的“跟随 AI”开关、“暂停跟随”“回到讨论位置”“查看全局”。首次进入新空间可默认开启，但记住用户关闭选择。
- 用户一旦手动拖动画布、缩放、拖动节点或编辑正文，立即暂停自动镜头，不使用短定时器偷偷夺回控制；由用户点击恢复。
- 用户正在输入、框选或编辑时不平移画布。
- 聚焦控制不改变当前选中节点，不自动打开编辑器，不自动选中待删除对象。
- 多目标已在视口安全区域时，只高亮，不移动；每条回复默认至多一次自动镜头运动，其他段落提供可点击引用。
- 流式回复按完整语义段落产生展示事件，不按 token 连续移动。不做自动轮播，不假设用户已读到某段。
- 点击历史消息里的节点引用可重新定位；若节点归档或删除，给出说明，不导航到错误对象。
- 跨子空间引用默认显示“前往该节点”按钮，需要用户点击才切换空间；不要打断用户当前编辑位置。
- 消息重试、断线恢复、组件重渲染不得重复播放镜头事件，用消息和事件 ID 去重。
- 多轮请求同时返回时，仅当前 scope 与有效版本的事件可控制画布，旧回复保留文字但不抢镜头。

### 9.5 视口计算与响应式

前端根据实际画布容器和节点包围盒计算相机：扣除 AI Dock、节点详情面板、工具栏占用及安全边距，不以整个浏览器窗口为中心。

- 用 ResizeObserver 等现有机制感知容器变化，侧栏伸缩后在未暂停跟随时适度重算。
- 使用 React Flow 对应版本提供的视口 API；具体方法名实施时核对依赖。
- 单节点限制最大缩放，节点群限制最小可读缩放；目标太分散时显示概览和局部入口，不无限缩小到字不可读。
- 动画建议 300–600ms，尊重 `prefers-reduced-motion`，降低运动时直接定位或仅高亮。
- 小屏一次保留一个主要面板，不能照搬桌面左右挤压布局；用户可切换对话与画布。
- 每个 scope 保留用户浏览位置，返回上层优先恢复旧视口，不强制重置全局。

新增节点可在草稿层预览。确认后在当前局部附近安排新节点，尽量避让并固定用户已有位置；全面重排必须用户主动触发。

## 10. 数据与接口落地要求

实施前提交“现有字段 → 复用/扩展字段”映射，不直接照搬下面概念名建表：

- Node：归属、父节点、正文、规划属性、版本、归档状态。
- Relation：两端、类型、说明、来源、版本。
- NodeAnalysis：scope、输入版本、诊断/策略/未知项与状态。
- Evidence：内容摘要、来源定位、适用范围、时间、核验状态。
- Conversation：所属 scope、消息、被引用对象、分析和提案关联。
- LayoutPreference：用户、scope、节点位置/视口；业务事实不放在布局字段。
- Proposal：基准版本、动作、影响分析、确认状态、临时引用映射。

布局与 viewport 是用户偏好，不影响任务完成状态。真实计划和正文以数据库为准，不能新增 localStorage 作为业务主存储。

API 至少覆盖：局部图读取、节点及正文更新、关系增删改、scope 对话、提案预览确认、布局保存、全局排期预检。路径和字段以现有约定扩展，不在文档中虚构已存在端点。

Pydantic 为契约权威，生成共享 schema 并更新前端类型及契约检查。需要迁移则提供 Alembic 迁移、备份方案、旧数据兼容策略和 SQLite/PostgreSQL 验证；禁止删库重建解决兼容问题。

## 11. 分批建设与交付顺序

### A. 自由关系图与节点空间

先落地非线性关系、任意层级创建、正文编辑、子空间与稳定 ID、持久化和权限。此阶段即使模型不可用，用户也能完整建图。

### B. 有范围的规划智能体

实现上下文整理、局部分析状态、动态追问、策略说明、渐进拆解、统一提案及冲突校验。先做一个节点从讨论到计划确认的完整纵向闭环。

### C. 对话与画布联动

在 B 的结构化引用上实现镜头协议、跟随控制、分组聚焦、面板适配和不抢操作。不能仅实现“每条消息后 fit 全部节点”。

### D. 全局排期与执行复盘

接回已有排期/执行服务，补齐多依赖与跨空间容量检查、局部重排、复盘反馈。保留已有可用功能，不重写一套 Today。

每批都需可运行的本地预览、测试结果、已知限制与修改说明，再进入下一批。最终交付必须覆盖 A–D，不能只完成 UI 或只接通模型就称完成。

## 12. 验收场景

以下同时作为自动化测试和人工体验脚本；使用隔离测试数据，不修改用户真实计划。

1. **空白与注册**：新账号注册后没有示例空间；创建新空间后无保研内容和预置聊天。
2. **手动建图**：不开 AI，在根画布和两层子画布分别创建节点、正文和关系；刷新后都存在。
3. **非线性依赖**：创建 A、B、C、D，A/B 都是 C 前置，C 是 D 前置；D 不能早于 C，C 不能早于任一前置；普通关联不影响排期。
4. **环与权限**：C 依赖 A 后再让 A 依赖 C 被服务端拒绝；无向关联闭环可存在；跨用户节点引用和连线被拒绝。
5. **进入与返回**：进入节点时其 ID 不变；编辑子节点后回到总空间可见变化，无复制节点、重复工时和双份任务。
6. **正文理解**：正文写“只能周末做”，下一轮规划能引用这一信息；用户改成“周二也可做”后旧分析标记过期，不能沿用旧限制而不说明。
7. **主动分析**：输入模糊目标时，AI 先给初步结构和依据，再问关键问题；不把“你准备怎么拆”当作主要回答；已有信息不重复索要。
8. **范围控制**：在项目 A 内要求细化，只生成 A 范围内提案；涉及项目 B 时明确展示越界影响并请求确认。
9. **提案一致性**：确认前正式图不改变；确认两次不重复创建；生成提案后手动改节点，旧提案不能覆盖新内容；失败回滚。
10. **相机联动**：AI 引用两节点时能聚焦两者和关系；侧栏展开后两者仍不被遮挡；只引用文字但不存在的节点不移动镜头。
11. **用户优先**：手动拖动/编辑时暂停跟随；旧流式事件和历史回复不抢镜头；恢复按钮可回到讨论位置；减少动画设置生效。
12. **草稿显示**：未确认的新节点只能在明确的草稿层展示；拒绝后消失，正式计划不受影响。
13. **全局容量**：两个空间共用一周 6 小时预算，不能分别各排 6 小时；容量不足时给出取舍，不伪造安排成功。
14. **执行重排**：一个任务延期后，仅调整相关后续任务并展示上层影响，不无条件重做整棵图。
15. **异常降级**：模型、检索或数据库失败分别有明确提示；模型失败不影响手工建图，数据库失败不能显示已保存。
16. **主题和响应式**：桌面及手机宽度检查登录、画布、正文、关系弹窗、任务和时间线，不残留黑色背景、不遮挡核心按钮。

建议额外用约 300 节点、500 关系的测试空间检查局部加载、拖动、文本编辑和镜头运动；记录机器、数据规模与测量结果，不编造性能通过。布局算法不能在每个流式 token 到达时运行。

## 13. Claude 最终交付清单

- 实际架构与现有代码的映射、明确的改动范围。
- 数据模型、迁移、契约及兼容策略；现有用户数据保留证明。
- 四批功能可运行实现，新增测试、回归测试及真实命令结果。
- 自动化测试使用 stub/隔离库，与真实模型验收分开报告；真实模型调用来源和降级状态如实记录，不输出密钥。
- 真实模型演示至少覆盖一次根目标拆解、一次子节点深入、一次关系引用聚焦；产生的测试记录可识别，不混入用户工作空间。
- 桌面/窄屏截图与画布跟随演示；注明哪些是人工验证。
- 最终本地预览地址、启动方式、已知问题及未实现项。

不要只交 Prompt、静态原型或一份“计划已接入”的文字说明。验收核心是：用户可以自己建图，AI 能读懂当前层级与关系，双方围绕同一份内容讨论，画布能有节制地跟随讲解，计划可以可靠保存、排期和迭代。
