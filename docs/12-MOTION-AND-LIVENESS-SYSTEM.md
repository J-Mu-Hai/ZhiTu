# 知途 Motion & Liveness System

> 状态：v1.0，2026-09-28。本文定义 Web 端统一的“生命感”系统。它是视觉与交互规范，不改变 Growth State、计划写入规则、AI 提案确认或排期语义。

## 1. 目标与原则

知途的动态感不是装饰动画，而是帮助用户理解三件事：

1. 什么刚刚发生了；
2. 系统此刻正在处理什么；
3. 哪个对象与当前讨论有关。

统一原则：

> 平时几乎察觉不到，操作时能感到它是活的。

所有动效必须满足：

- **有原因**：没有状态变化，不播放反馈动画。
- **有边界**：一个页面只选择一个主要动态来源。
- **不冒充事实**：没有模型运行时，不得播放“AI 正在分析”；没有保存成功时，不得播放完成反馈。
- **不抢内容**：文字、节点和计划结构永远比动画更重要。
- **可以关闭**：系统开启 `prefers-reduced-motion` 时必须降级。
- **可中断**：切换视图、连续拖动或快速操作时，动画不得阻塞下一次输入。

## 2. Motion Tokens

所有页面只允许使用下列令牌，不在组件内随意发明时长或缓动。

| Token | 建议值 | 用途 |
| --- | ---: | --- |
| `--motion-press` | 100ms | 按下、checkbox 收缩 |
| `--motion-hover` | 140ms | hover、端点放大、线条变清晰 |
| `--motion-state` | 220ms | 卡片状态、按钮状态、节点创建 |
| `--motion-panel` | 260ms | 菜单、阅读面板、AI Dock 开合 |
| `--motion-focus` | 380ms | 画布聚焦、选中节点 |
| `--motion-space` | 520ms | 进入或离开 NodeSpace |
| `--motion-ai` | 680ms | AI 语义高亮、关系流动光点 |
| `--motion-ambient` | 32s | 大范围环境光晕 |

缓动只使用两类：

```css
--ease-ui: cubic-bezier(.22, .8, .32, 1);
--ease-space: cubic-bezier(.2, .72, .24, 1);
```

`--ease-ui` 用于按钮、卡片和面板；`--ease-space` 用于画布与空间切换。不要使用明显回弹的 spring。若画布库必须使用 spring，阻尼应足够高，不能出现第二次明显反弹。

## 3. 环境生命感

### 3.1 暖白环境光

只在成长空间、工作台和首页的大面积空白背景上使用。由两层非常大的浅雾蓝、米白径向光晕组成，以 32 秒左右周期移动 2%–4% 的视口距离。

- 单层不透明度：`0.025–0.055`；
- 不改变正文区域对比度；
- 不在登录表单、对话正文、节点卡片内部播放；
- 页面失焦或标签页不可见时停止；
- `prefers-reduced-motion: reduce` 下完全静止。

它必须是“关闭动画后才略有察觉”的程度。如果用户能一眼指出背景在移动，说明幅度过大。

### 3.2 空状态

空状态图标可在页面停留 12–18 秒后播放一次 2–3px 的轻微位移，持续不超过 600ms。用户发生任何输入后重新计时。禁止连续上下漂浮或持续旋转。

## 4. 对象生命感

### 4.1 节点状态矩阵

| 状态 | 表现 | 时长 | 是否循环 |
| --- | --- | ---: | --- |
| 普通 | 完全静止 | — | 否 |
| 新创建 | `opacity 0→1`，向上 5px 回到原位，阴影同步出现 | 220ms | 否 |
| hover | 边框略清晰、阴影增加、连接端点放大到 1.18 倍 | 140ms | 否 |
| 拖动中 | 节点提升 2px、阴影加深，相关线条提高清晰度 | 跟随手势 | 否 |
| 被选中 | 柔和外环出现，不缩放节点本体 | 220ms | 否 |
| 被 AI 引用 | 鼠尾草绿或浅蓝外环呼吸一次 | 680ms | 仅一次 |
| 待用户确认 | 边缘亮度在很小范围内缓慢变化 | 2.8s | 可循环，确认或拒绝即停 |
| 已完成任务 | checkbox 收缩后回弹，文字和卡片过渡到完成色 | 120ms + 220ms | 否 |
| 保存失败 | 不抖动；显示稳定错误状态和重试入口 | 220ms | 否 |

禁止所有节点持续漂浮。动画只作用于状态发生变化的节点，不能因为重新渲染整张画布而让全部节点重新淡入。

### 4.2 连接线

连接线是工作台最主要的生命感来源。

- 默认保持静态、低对比度；
- hover 或拖动某个节点时，仅与它直接相连的线在 140ms 内变清晰；
- 新建连线成功后，从 source 到 target 播放一次 220–320ms 的绘制动画；
- AI 明确引用一条已有关系时，沿关系方向播放一次低亮度光点；
- `depends_on` 与 `influences` 按 source → target 运动；`related_to` 不表达方向，只做一次从两端向中间收束的微光；
- 光点不得持续循环，也不能在 AI 只是输出普通文本时出现。

关系动画必须读取真实的 relation id。不能靠标题模糊匹配，否则同名节点会亮错。

### 4.3 连接端点

鼠标进入节点 18px 范围时，端点从 8px 放大至约 10px；开始拖线后目标端点才出现第二级高亮。端点的命中区域可大于视觉尺寸，但不能让节点正文区域误触发连线。

## 5. 无限画布与 NodeSpace

### 5.1 平移和缩放

- 平移释放允许极轻的减速，但额外滑行距离不得超过释放前最后一帧速度对应的 40–80ms；
- 缩放围绕指针或当前视觉中心进行；
- 缩放过程节点几何可连续变化，文字应保持清晰，不做模糊滤镜；
- 程序触发的聚焦使用 320–450ms；用户直接滚轮缩放不强行加长到该时长。

### 5.2 进入子空间

进入 NodeSpace 的品牌动作：

1. 被进入的节点在原位置轻微放大约 1.025 倍；
2. 其他节点和关系线降低透明度；
3. 画布视觉中心移动到该节点；
4. 子空间内容从中心周围展开；
5. 面包屑和视口状态同步更新。

总时长 420–600ms。动画只是导航的表现，不能延后 URL/Provider 状态切换，也不能在动画中禁止后退。快速连续进入时取消上一段动画并从当前视觉状态继续。

返回上层使用相反的视觉方向，但不是逐帧倒放：当前子空间收束，父层内容淡入并回到该层保存过的 viewport。

## 6. AI 状态动效

### 6.1 知途状态标识

不用传统三个跳点。使用“点 → 生长线 → 分叉 → 收束”的细线标识，且文字永远与动画同时存在。

| 真实状态 | 图形阶段 | 文案示例 |
| --- | --- | --- |
| 已提交请求、正在构建上下文 | 一个点向外长出短线 | 正在读取当前节点与相关内容 |
| reasoner 已开始、等待模型响应 | 细线分成两到三支 | 正在分析目标、关系与限制 |
| 响应已收到、正在形成提案/分析 | 分支向一个方向收束 | 正在整理建议与可确认的调整 |
| 降级到规则兜底 | 动画停止，显示稳定标识 | 当前未使用模型，以下是规则建议 |
| 失败 | 动画停止，不循环重试 | 这次没有完成，可重试 |

前端只有拿到可证明的运行状态时才推进阶段。后端目前若只能提供“等待回复”一个状态，第一版只能播放单一的生长/收束循环，不得假装知道正在进行哪一步。

### 6.2 AI Dock

- 空闲时完全静止，使用极轻阴影；
- 输入框聚焦或发送消息后，边框亮度提高一个等级；
- AI 输出期间仅顶部状态标识运动，整个面板不发光；
- 用户拖动画布时，Dock 阴影和背景不透明度略降，指针释放后在 220ms 内恢复；
- 被 AI 引用的节点可以高亮一次，但 Dock 与画布不能同时大幅运动；
- 面板打开/关闭使用 220–300ms，关闭后立即归还画布宽度。

## 7. 各页面唯一的主要动态

每个页面只指定一个主要动态来源：

| 页面 | 主要动态 | 次要反馈 |
| --- | --- | --- |
| 成长空间列表 | 新空间创建后卡片淡入并归位 | 卡片 hover 提升 1–2px |
| 工作台路径 | 节点与关系线状态 | AI 引用高亮 |
| 时间线 | 当前日期指示与视窗平滑移动 | 新排期短暂高亮 |
| 任务 | 完成状态过渡 | 筛选切换淡入 |
| 排期 | 场次新增、移动和冲突提示 | 日容量变化过渡 |
| 随笔 | 输入框和阅读面板展开 | 新随笔加入列表 |
| 首页 | 当前日期/所选日期切换 | 完成反馈 |
| AI Dock | 知途状态标识 | 面板开合 |

页面的主要动态已经播放时，环境背景仍保持极弱，其他次要元素不得再增加循环动画。

## 8. 组件级细节

### 按钮

- hover 只改变表面色、边框或图标位置 1px；
- press 使用 0.98–0.99 的短暂缩放，仅限实体按钮；
- 图标按钮不得旋转或弹跳；
- disabled 不播放任何 hover/press 动画。

### 菜单与面板

- 从触发器方向移动 4–6px 并淡入；
- 关闭比打开略快；
- 焦点必须随开关正确进入和返回，动画不能延误键盘焦点；
- `<dialog>` 打开时背景只淡化，不缩放整个应用。

### 随笔

- 输入区展开时只改变自身高度，不推动页面横向位移；
- 列表切换阅读对象时，正文使用 140–180ms 淡入，不从左右滑动；
- 发布成功后新条目淡入；当前版本未持久化时不能播放“已安全保存”的语义反馈。

### 首页和任务

- checkbox 反馈必须等真实写入成功，或明确采用可回滚的乐观更新；
- 写入失败时恢复原状态并显示错误；
- 不使用彩带、粒子或大面积庆祝动画。

## 9. Reduced Motion 与性能

### 9.1 降级规则

在 `@media (prefers-reduced-motion: reduce)` 下：

- 环境光停止移动；
- NodeSpace 改为 100ms 以内的淡入淡出或直接切换；
- 关系流动光点改为静态高亮；
- 面板不做位移，只改变透明度；
- checkbox 保留颜色/图标变化，不缩放回弹；
- 禁用平移惯性。

### 9.2 性能规则

- 优先只动画 `transform` 与 `opacity`；
- 不对大面积画布持续动画 `filter`、`box-shadow` 或渐变位置；
- 环境光用独立伪元素，不触发节点重排；
- 画布拖动期间暂停环境动画与非必要 AI 装饰；
- 关系光点数量同时最多 3 个；
- 页面不可见时停止所有循环动画；
- 动效不能导致 ReactFlow 节点位置被重复写入布局接口。

## 10. 明确禁止

- 满屏粒子、彩带、烟花；
- 所有节点持续漂浮；
- 明显且持续的呼吸光；
- 大面积持续流动渐变；
- 所有按钮都有弹跳；
- AI 输出时整个 Dock 边框循环发光；
- 用动画掩盖网络等待、写入失败或模型降级；
- 未经用户确认，就用“成功生长”动画暗示 AI 提案已经写进计划。

## 11. 实施批次

### 批次 A：低风险基础

1. 建立 CSS Motion Tokens 与 reduced-motion 总开关；
2. 按钮 hover/press、菜单与 Dock 开合统一；
3. 节点 hover、拖动、创建和完成反馈；
4. 节点 hover 时直接关系线变清晰；
5. 随笔输入与阅读切换。

这一批不要求后端改动。

### 批次 B：画布语义动效

1. 新建关系绘制；
2. AI 引用节点与关系的单次高亮；
3. NodeSpace 进入/退出转场；
4. 程序聚焦与视口移动统一。

开始前必须明确 AI 响应如何返回“引用了哪些 node/relation id”，不能用标题猜测。

### 批次 C：AI 状态标识

1. 确认后端能真实暴露哪些阶段；
2. 实现状态机和知途专属线条标识；
3. 区分真实模型、规则兜底、失败和重试；
4. 加入真实模型连续体验验收。

若后端暂时只有 pending/success/error，就只实现这三态，不伪造“分析关系”等内部阶段。

## 12. 验收标准

自动化与人工验收至少覆盖：

1. `prefers-reduced-motion` 下不存在持续移动元素；
2. 普通节点静止，新建节点只播放一次；
3. hover 节点只增强直接相关的线；
4. AI 没有引用对象时画布不出现语义高亮；
5. 规则兜底不显示“模型正在分析”；
6. 完成任务写入失败时不保留完成动画后的视觉状态；
7. 快速连续切换 NodeSpace 不锁死输入、不丢 viewport；
8. 动效前后节点坐标与后端 layout 完全一致；
9. 桌面、窄屏和 125%/150% 缩放下没有面板溢出；
10. 画布含 80 个节点时，拖动期间没有明显持续掉帧；
11. 所有动画结束后焦点仍在正确的交互对象上；
12. 去掉动画后，所有功能与状态仍然可理解。

## 13. 第一阶段完成定义

第一阶段不是“页面到处都在动”，而是：

- 所有页面共享一套 Motion Tokens；
- 普通状态保持安静；
- 节点、关系、任务完成和 AI 等待有准确反馈；
- reduced-motion 完整可用；
- 动画不会改写业务状态，也不会掩盖失败；
- 每个页面只有一个明确的主要动态来源。

达到这些条件后，再评估 NodeSpace 品牌转场和更细的 AI 语义动画。
