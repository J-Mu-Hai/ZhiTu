# 阶段 9：Agent 可观测性与时间线收口实施计划

## 1. 目的与完成定义

阶段 8 已使目标规划能够形成“根目标 → 战略路线 → 阶段”的主结构，但本地体验仍有两个明显断点：

1. 模型请求停住、超时、结构校验失败或提案版本冲突时，用户、Pi 和维护者看不到当前卡在哪一步，只能从对话区的大段警告反推。
2. 时间线仍保留两套时间轴表达、顶部的尺度/导航控件和底部概览覆盖条，视觉层级与工作台暖白主题不统一。

本阶段完成后应达到：

```text
任一 Agent turn
  → 开始即写入可查询的运行状态
  → 模型 / 工具 / 校验 / 持久化每一步都有脱敏进度
  → 本地用户可打开“运行记录”诊断卡，知道正在等什么、失败在哪里、能否重试

时间线
  → 中央唯一时间轴
  → 在轴上直接标记任务 / 里程碑 / 截止日
  → 鼠标/触控板平移缩放，不再保留上下两条轴或无用控制条
```

这不是暴露模型 Chain-of-Thought 的功能。诊断入口只呈现系统可审阅的事件、工具名、耗时、状态、用户可理解的失败原因和脱敏元数据。

## 2. 现状与不可破坏边界

### 2.1 可复用能力

| 已有能力 | 本阶段用途 |
| --- | --- |
| `reasoning_states`、`tool_call_records` | 已持久化的 turn、工具调用和结果摘要；扩展为可读运行轨迹的基础 |
| `AgentTurn`、`agent_loop_service`、真实模型超时/失败处理 | 在每个边界写入进度与终态 |
| `ConversationPanel` | 将“画布有问题待回答”从正文区移为紧凑顶栏状态；提供“运行记录”入口 |
| `TimelineView.tsx`、`features/growth/timeline.ts` | 保留时间计算、任务排布、键盘/滚轮平移缩放能力 |
| `tokens.css`、暖白工作台主题 | 消除时间线独立的深蓝/冷蓝体系 |

### 2.2 必须保持

- 不记录、不返回、不显示 LLM 原始 prompt、密钥、token、Cookie、连接串、用户敏感查询或隐藏思维链；
- 研究结果的来源继续走已有 citation 边界；诊断记录只显示来源数量/域名等必要摘要；
- 不改变 `proposal → 用户确认 → 版本校验 → 事务写入`；诊断仅解释为何未写入；
- 不改变时间线的数据语义：截止日期不等于日程，改具体安排仍走“排期”；
- 时间线移除控制条后仍可鼠标/触控板平移缩放，并保持键盘无障碍操作；
- 不删除未排期节点，只改变其低干扰入口；
- 不为了“调试方便”开放匿名 API，也不让生产用户默认看到内部诊断。

## 3. 交互规格

### 3.1 本地 Agent Trace Inspector

#### 入口与可见性

- 在右侧“一起思考”标题栏放一个低干扰的“运行记录”图标按钮；不在每条对话中常驻塞技术状态。
- 本地开发环境默认可用；其他环境由显式 `AGENT_TRACE_UI_ENABLED` 配置决定，默认关闭。
- 用户单击打开右侧抽屉/浮层，不挤压画布和对话正文。关闭后不影响正在运行的 turn。
- 若当前 turn 正在运行，标题按钮显示小状态点；失败时显示可见但不过度抢眼的错误点。不是靠动画制造“还在工作”的错觉。

#### 用户可见内容

按时间倒序显示最近 20 个 turn，每项只显示：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 触发来源 | 进入空间 / 回答问题 / 重新生成路线 | 来自显式 `AgentTurnTrigger` |
| 当前阶段 | 等待模型 / 公开研究 / 校验路线 / 写入草案 / 已完成 | 有限状态集合 |
| 状态与耗时 | 运行中 · 8 秒 / 失败 · 6 秒 | 必须由服务器时间计算 |
| 安全摘要 | “模型返回的路线结构不完整，已重试 1 次” | 不显示原始模型文本或推理链 |
| 工具摘要 | “公开研究：成功，3 条来源” | 仅工具名、结果、耗时、数量/域名 |
| 下一步 | 重试 / 查看可读原因 / 无需操作 | 只显示实际可执行的动作 |

- 正在进行的模型调用在发请求前即写为 `waiting_model`；超过配置阈值（建议 25 秒）显示“仍在等待模型响应”，并持续显示最后心跳时间。
- 模型超时、网络错误、结构校验失败、提案版本冲突、预算耗尽都必须区分显示，并给出可读、非技术化原因。
- 提供“复制诊断摘要”按钮：复制脱敏 JSON/纯文本，包含 workspace/turn 的短 ID、触发来源、状态转移、耗时、错误代码、工具摘要、当前配置开关；不含敏感内容。它是 Pi 或维护者排障的交接入口。
- 诊断详情默认不显示用户消息全文；仅在本地、用户显式点击且已有数据脱敏策略时可显示长度/哈希/是否含附件，仍不显示原文。

#### 后端契约与状态

在既有 `reasoning_states` / `tool_call_records` 基础上实施；若现有字段不足，使用最小迁移增加如 `started_at`、`last_progress_at`、`current_step`、`attempt`、`terminal_code`、`safe_summary`。不要另建一套与实际执行脱节的前端状态。

建议闭集步骤：

```text
queued
→ resolving_context
→ waiting_model
→ running_tool
→ validating_output
→ persisting
→ completed | failed | timed_out | cancelled
```

- 所有步骤更新由服务端真实执行边界写入；前端轮询只读取，不能自行猜测“完成”。
- 读取 API 必须按 workspace 授权，分页、时间范围和上限固定；不得返回 ORM 原始 JSON。
- `retry` 仅对安全、可重试且尚未写入的失败 turn 开放；沿用幂等键/版本检查，禁止把已确认提案重新写入。
- 现有历史记录字段不足时返回 `unavailable`，不能伪造实时细节。

### 3.2 对话区让出效率

当前“画布上有待澄清问题”卡与画布卡重复，并占用对话正文空间。

- 将其移到 ConversationPanel 标题栏下方的紧凑、可固定状态条：`待回答问题 1 · 定位到画布`。
- 它只在存在活动问题时显示；高度约 28–32px，不展示完整问题正文、理由、来源或选项。
- 单击“定位到画布”继续复用既有 focus 行为；完整回答只在画布的 Question Node 中进行。
- 对话正文不再渲染重复的“大问题提示卡”。
- `INPUT_CHANGED` / 版本冲突这类状态也应进入 Trace Inspector 的可读记录；对话区最多保留一行可关闭结论，例如“本轮未应用：信息已更新 · 查看运行记录”，不得显示大块长文。

### 3.3 时间线：中央唯一时间轴

#### 删除的冗余界面

移除以下视觉入口及其占位：

- 左上“年 / 季度 / 月 / 周 / 天”尺度按钮；
- 右上“上一时段、缩小、滑条、放大、今天、下一时段”控制组；
- 底部 overview/minimap 及其蓝色 viewport 覆盖条；
- 顶部独立 ruler/第二套日期轴与大段操作说明。

删除控件不等于删除能力：

- 普通滚轮/触控板拖动继续平移；Ctrl/⌘ + 滚轮继续缩放；
- 键盘方向键平移，`+` / `-` 缩放，`Home` 回到今天；
- 用简短 tooltip/无障碍 `aria-describedby` 提示一次，不再用常驻说明条占空间；
- 当前缩放尺度应由 `density` 自动推断，日期刻度按密度自适应，不需要用户先选“月/周”。

#### 单轴排布

- 画布中央只有一条主时间轴；年/月/周标签、刻度、今天标记和任务锚点都围绕该轴排布。
- 任务、阶段、里程碑和截止日卡片从中轴上下错开，用引线连接其唯一时间点/时间段；保持现有重叠规避算法并以测量尺寸为准。
- 不再额外画顶端 ruler；标题日期和刻度必须与中轴同一套 `start/density` 计算。
- 空状态文字不覆盖中轴；未排期节点改为低干扰的 `未排期 N 项` 小入口，点击后打开节点列表/跳转任务视图。数据仍可发现，但不使用整条底部横幅。
- 选中节点的日期编辑可以保留为紧凑 inspector/浮层；它不能再把第二条时间线或大面积栏带回来。

#### 主题

- `TimelineView.module.css` 和相关样式必须使用现有暖白主题 token（surface、line、text、muted、blue-ink、semantic category），不保留独立的硬编码深蓝面板/覆盖层。
- “今天”保留清晰而克制的蓝色语义；选中、风险、已完成、里程碑不能只依赖颜色，需有形状/文字辅助。
- 不增加大面积蓝色背景、厚覆盖条或与路径页不一致的阴影。

## 4. 分步实施与提交

### 步骤 1：可观测性模型、读取 API 与脱敏

- 审计 `reasoning_states`、`tool_call_records`、`agent_loop_service`、模型调用/超时、失败处理与已有 config；
- 添加最小状态字段和迁移（仅在确有字段不足时）；
- 在真实执行边界写入状态与心跳；
- 新建受授权的 trace read API、Pydantic contract、红线脱敏函数与复制摘要格式；
- 单测超时、模型错误、工具错误、非法路线结构、提案版本冲突、重试与跨 workspace 授权。

提交：`feat(agent): expose sanitized turn trace for local diagnostics`

### 步骤 2：Trace Inspector 与对话区收口

- 实现本地/开关受控的 Trace Inspector；
- 支持运行中轮询、终态停止轮询、复制诊断摘要、受控重试；
- 将待回答问题改为标题下紧凑状态条，移除对话流中重复的大卡；
- 将 `INPUT_CHANGED` 等长警告改为一行结论并链接到运行记录；
- 补前端可访问性、窄屏和无诊断权限状态。

提交：`feat(conversation): add local agent trace and compact question status`

### 步骤 3：时间线单轴化与主题统一

- 删除顶部工具条、顶部 ruler、底部 overview；清理失效事件、状态和 CSS；
- 将标签/刻度/今天/任务锚点统一到中央主轴；
- 保留滚轮、触控板、键盘快捷键与任务选择；
- 将未排期内容改成小入口，统一暖白 token；
- 通过视觉和交互测试验证不同缩放级别、空状态、任务重叠和窄屏。

提交：`fix(timeline): simplify to one centered axis`

## 5. 验收标准

### Agent Trace

1. 新建 Agent turn 后，模型请求仍在等待时，Trace Inspector 能显示“等待模型”与已耗时。
2. 模型超时、网络错误、工具失败、非法结构、版本冲突分别有不同的可读终态；没有 prompt、密钥、用户原文、隐藏思维链泄漏。
3. 复制诊断摘要可供 Pi 排障，内容脱敏、包含状态序列和错误代码。
4. 没有 trace 功能开关或在生产环境关闭时，普通用户看不到入口/API 内容；已有主流程不受影响。
5. retry 不会重复写入已经确认的提案，跨空间读取被拒绝。

### 对话区

1. 存在活动问题时，标题下只出现一条紧凑状态；对话正文没有重复问题卡。
2. 点击定位能聚焦正确 Question Node；不影响画布回答。
3. 版本冲突提示不再占据大块正文，仍能定位到 trace/可执行下一步。

### 时间线

1. 页面上仅有一条中心主时间轴，无尺度按钮、导航/缩放控制组、overview 蓝色覆盖条或独立顶部 ruler。
2. 鼠标/触控板、Ctrl/⌘+滚轮、方向键、`+`/`-`、`Home` 均可用。
3. 任务、里程碑、截止日能在中心轴上正确定位；选中和密集任务不重叠或可通过聚合入口发现。
4. 未排期项目仍可发现，且不会生成整条底部横幅。
5. 暖白主题与路径页一致；文本与交互元素满足现有可访问性对比度要求。

## 7. 非目标

- 不展示模型的原始思维链；
- 不实现远程生产运维后台或多用户监控；
- 不以 trace 为名把真实 API Key 写入数据库或浏览器；
- 不改变研究提供方、路线优先状态机或 proposal 确认机制；
- 不为时间线重新引入第二套概览轴、顶部工具栏或大面积蓝色覆盖层。
